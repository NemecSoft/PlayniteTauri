PlayniteTauri — 系统架构

Monorepo · Tauri v2 · React 19 · Rust + SQLite · 绿色存储
自顶向下：前端 → IPC → Rust 核心 → 存储
前端层 Tauri IPC Rust 核心 共享状态 持久化存储 文件系统 / 外部 同步调用 异步 / 事件

数据流

1React UI（src/components）
2Tauri 命令（src/api/client.ts → invoke）
3Rust 命令（crates/yungame-core/src/commands/*.rs）
4AppState（Mutex<Database> · ProcessManager · PluginHost）
5SQLite（library/library.db）/ 进程启动 / 文件系统

关键设计决策

  • Monorepo 隔离：每个 Tauri 应用（desktop / admin）各自独立的 tauri.conf.json / frontendDist，只嵌入各自前端，避免"管理端误加载客户端前端"、双窗口、cdylib 链接失败。
  • DB 用 Mutex 包裹：rusqlite::Connection 是 Send 但非 Sync，需 Mutex 提供内部可变性。
  • 完全绿色存储：settings.rs 用 current_exe() 定位数据根；debug 构建固定指向项目根 release/。
  • 共享核心库：yungame-core 提供 run_client / run_admin 两个 Builder 工厂，供两个 Tauri 应用复用。
  • 前端相对路径（base: "./"）：保证资源在 tauri://localhost 下可解析。
